# AGENTS.md — Schedule packages

These rules supplement the repository and package instructions for `packages/schedule/*`.

- The owning Session's version-1 `schedule/change` stream is the only durable Schedule business-state authority. Version-2 `schedule/delivery` is an `ignorable: true` auxiliary outbox row in that same stream, never another scheduler, queue, or store; it validates/reserves delivery but only matching v1 dispatches advance active records.
- A normal Session folds its complete log. A fork derives active Schedule state only from events at or after `SessionHeader.seedLength`; it never inherits an active parent reminder.
- Every Schedule management operation that reads or decides from the fold first awaits `ctx.sessions.flush(session)`. Create and an actual delete await a second barrier after append; a failed barrier returns the stable uncertainty result instead of inferring durability from the live log.
- Runtime owners attach only to future live root Agents while the plugin is loaded. They do not scan persisted Sessions, adopt already-published roots, wake cold Sessions, register global tools, or delete durable records during teardown.
- A launcher may provide one closed `ScheduleDeliveryAdmission` before publishing a root Agent. Schedule honors it while the provider is still loading; absence means open. Closed admission freezes every delivery path but leaves version-1 management available, and `open()` is one-way.
- Due handling rechecks the wall clock and exact live owner, claims the public idle-maintenance phase, appends one pending outbox row plus the complete ordered v1 dispatch batch, and crosses one durability barrier before `followup()`. Exact durable carriers form an occurrence-id union; after an old partial carrier, the original deterministic message id renders only the residual occurrences. Exact overlaps caused by a forced old-pin crash are credited once so current recovery adds no further copy, but they do not erase or hide a duplicate already produced by the old runtime. Complete is appended and checkpointed only after the union covers the batch. Recovery appends missing v1 mirrors before enqueue and recognizes only exact current or dispatch-prefix-reconstructed old-pin Schedule messages. An exact old message for a later occurrence stays outside the pending union once its matching v1 dispatch is present; a torn message-before-dispatch prefix faults closed. A delete after pending ends future active state but not the reserved occurrence.
- Schedule-owned Inbox messages are visible but producer-owned: the Host queue-mutation API must reject edit, steer, and cancel for them at its native boundary. Delivery recovery treats a failed duplicate removal as a fault and never closes the outbox row.
- Rollback readers may ignore `schedule/delivery` only because every envelope is marked ignorable and all active-state changes remain in v1. Before selecting an old pin, the updater must quiesce current Agents, flush live Sessions, enumerate `ctx.sessionPersistence.list()`, inspect every header, and require `foldScheduleEvents(inspection.events, inspection.meta.seedLength ?? 0).pendingDelivery === undefined`; any flush, list, inspect, or fold failure blocks rollback. This is a native projection over the same Session stream, not another store. Bypassing that admission fence can let consecutive old-pin crash recoveries duplicate an occurrence; current recovery can contain but cannot undo it. Running an old Host also lacks producer-queue protection, so no queue mutation while downgraded remains required; do not claim unconditional exactly-once model effects or user acknowledgement.
- Rule math and durable transition logic stay pure and deterministic. Production uses the platform wall clock and segmented timers; tests supply explicit samples or fake timers without adding a production clock service.
