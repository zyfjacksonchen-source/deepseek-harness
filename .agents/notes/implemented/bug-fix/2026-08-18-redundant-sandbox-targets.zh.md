# Agent Note: 冗余沙箱目标

Status: implemented

[English](2026-08-18-redundant-sandbox-targets.md) | 中文

## 问题

模型调用可能重复当前 `sandbox_permissions` 值，或请求更窄的目标。将每个已提供目标都送入放宽校验器，会拒绝这些调用，尽管常驻策略已经授权该命令。把更窄目标当作执行降权同样不真实，因为执行器没有承诺低于常驻策略的逐调用约束。

## 决策

Bash 和 PowerShell 工具会在审批前根据常驻策略分类请求目标。目标与常驻模式相等，或常驻模式已经是 `danger-full-access` 时请求任何目标，都属于冗余请求：命令沿用未变的常驻策略运行，且不提示任何人。只有有效且严格更宽的目标才进入现有审批路径。缺少沙箱组合、模式格式错误、审批不可用、拒绝和取消仍然是失败关闭错误。

本决定细化了[沙箱决策](../feature/2026-07-06-sandbox.md)所拥有的升权行为。它不增加授权、持久状态、工具、执行器或逐调用降权路径。

## 曾考虑的替代方案

- **拒绝每个非放宽目标。** 否决，因为冗余模型字段不应阻止已经由常驻策略授权的命令。
- **按该次调用请求的更窄模式执行。** 否决，因为当前执行器约定不提供逐调用降权，而报告降权会夸大约束能力。
- **对已经处于最宽模式的会话隐藏升权字段。** 否决，因为工具 schema 是注册表全局的，而有效沙箱模式是按会话的。

## 后果

冗余 `sandbox_permissions` 参数不再产生工具错误或审批提示，也绝不会缩小或扩大命令的常驻权限。Bash 和 PowerShell 测试覆盖 `workspace-write` 与 `danger-full-access` 下的相等和更窄目标，同时保留无效组合、格式错误模式、真实放宽、拒绝、取消和审批不可用用例。
