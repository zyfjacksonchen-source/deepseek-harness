# Agent Note：持久提示符身份与冗余沙箱目标

状态：已实现

[English](2026-08-18-persistent-prompt-and-redundant-escalation.md) | 中文

## 问题

`terminal-bash` 把 `dsh> ` 认作受控可打印提示符，而 `tool-bash-persistent` 给 Bash 配置的是 `__DSH_PERSISTENT_BASH_PROMPT__ `。两者逐字节不一致，提示符就绪无法结算，每条持久命令都会落到静默回退。与此同时，模型调用有时会重复当前 `sandbox_permissions`；工具把这个未拓宽的目标当作失败升级，尽管常驻策略已经允许执行该命令。

## 决策

`terminal-bash` 现在采用持久工具的确切 31 字节提示符，包括末尾空格；现有终端测试锁定同一可打印值。Bash 与 PowerShell 工具把等于或低于常驻模式的请求目标视为冗余：无需审批，沿用常驻策略执行。只有有效且严格更宽的目标才进入现有 fail-closed `approveEscalation` 路径；未组合沙箱、模式格式错误、审批不可用、拒绝和取消仍然报错。

## 后果

提示符就绪可以由私有标记结算，无需等待静默回退。冗余权限字段不再把一条已获授权的命令变成工具错误或审批提示，也不会形成逐调用降权：命令仍沿用常驻策略，而任何真实拓宽继续遵循现有审批和 fail-closed 行为。该提示符仍是两个包中的重复私有字面量，由两侧测试和逐字节比较防止漂移。

## 考虑过的替代方案

- **从一个包导出提示符，并让另一个包新增运行时依赖。** 放弃；一个私有标记不足以让终端后端耦合到面向模型的工具包。
- **继续拒绝相等或更窄的目标。** 放弃；模型多余填写的字段没有请求更多权限，不应阻止已经由常驻策略授权的命令。
- **把更窄目标当作逐调用降权。** 放弃；当前执行器约定没有承诺这项覆盖能力，静默宣称更窄限制并不真实。

## 验证

- 两个常量的 UTF-8 十六进制均为 `5f5f4453485f50455253495354454e545f424153485f50524f4d50545f5f20`，长度均为 31。
- 终端、持久 Bash、Bash、PowerShell 与沙箱升级测试覆盖提示符就绪、冗余目标、真实拓宽、格式错误输入及缺失沙箱组合。
- 在 macOS 和 Linux 上以相同的进程型持久 Bash 命令实测提示符修改前后的延迟。
